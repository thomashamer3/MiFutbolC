## Conventions worth preserving

- Flat root module layout: one `snake_case.c` + `.h` pair per feature; only tests live in `tests/`.
- Naming: `snake_case` files/functions/variables; `PascalCase` structs/enums; `SCREAMING_SNAKE_CASE` macros.
- Module anatomy: `menu_<modulo>()` builds `MenuItem items[]` and calls `ejecutar_menu()`;
  the last entry is always `{0, "Volver"/"Salir", NULL}`.
- Main menu registration lives in `menu.c` (`struct MenuItemDefinition MENU_ITEMS[]`), with a
  `static void abrir_menu_<modulo>(void)` wrapper that calls `app_log_event()` then `menu_<modulo>()`.
- Data access: single global `sqlite3 *db` singleton (`db.h`) - never open a second connection.
- SQL: prepared statements with `?` placeholders; no concatenated user data; migrations via
  `PRAGMA user_version`; IDs via `obtener_siguiente_id(tabla)`.
- Return convention: `1` = success/true, `0` = failure/false, `-1` = error/not-found.
- UI: `ui_printf*`/`ui_puts` and `input_int`/`input_string`/`input_date` wrappers only.
- Cross-platform: paired `#ifdef _WIN32` / `#else` branches; `snprintf` over `sprintf`;
  `compat_port.h` supplies C11 Annex K shims on non-Windows.
- Comments and user-facing strings are in Spanish; generated SDD artifacts are in English.
- Export pattern: `<entidad>_csv/_txt/_json/_html` plus an `exportar_<entidad>_all()` aggregator.
